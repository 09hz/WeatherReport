# Task: Initialize Weather & Journal Application Backend

## Role
Act as a senior Python backend engineer working within an agentic development environment.

Your objective is to establish a clean, modular, and extensible backend foundation for a Weather & Journal web application.

This is an initial infrastructure task, not a complete application implementation.

Prioritize maintainability, security, clear separation of responsibilities, and minimal dependencies.

## 1. Repository Inspection

Before making changes:

1. Inspect the current repository structure.
2. Identify existing files, configurations, and dependencies.
3. Preserve existing functionality.
4. Briefly summarize the implementation plan.

Avoid unnecessary research, repeated file reads, or unrelated changes.

## 2. Application Requirements

Build the backend foundation using:

- Python 3.10+
- Flask
- SQLite
- Python dictionaries for application data
- Environment variables for configuration
- REST-style API endpoints
- pytest for testing

The application will eventually support two primary modules.

**Weather Module**
- Retrieve current weather conditions from an external API.
- Accept a city or location.
- Normalize weather responses into dictionaries.
- Allow weather snapshots to be saved to SQLite.
- Support retrieval of previously saved weather records.

**Journal Module**
- Create journal entries containing a title, date, location, and description.
- Store entries in SQLite.
- Retrieve and search previous entries.
- Optionally associate journal entries with saved weather snapshots.

Do not implement the frontend or advanced application features yet.

## 4. Backend Implementation

Implement the minimum functional foundation:

1. Flask application factory.
2. Configuration loading through environment variables.
3. SQLite connection management and schema initialization.
4. Weather and journal database tables.
5. Basic API route registration.
6. A health-check endpoint returning JSON.
7. Input validation and consistent error responses.

Implement basic journal creation and retrieval if practical.

For weather retrieval, create a provider interface or minimal adapter that can later connect to a real weather service.

Do not invent API responses or present placeholder weather data as real observations.

## 5. Environment Configuration

Create `.env.example` with placeholders such as:

```dotenv
FLASK_ENV=development
FLASK_DEBUG=false

DATABASE_PATH=instance/weather_journal.db

WEATHER_API_KEY=YOUR_WEATHER_API_KEY_HERE
WEATHER_API_BASE_URL=YOUR_WEATHER_PROVIDER_URL_HERE

SECRET_KEY=REPLACE_WITH_RANDOM_SECRET
```

Requirements:

- Never hardcode credentials.
- Never commit a populated `.env` file.
- Add `.env`, database files, and generated caches to `.gitignore`.
- Do not require real API credentials to start the application.
- Keep external weather requests disabled until a provider is configured.

## 6. Testing and Verification

Create pytest tests covering:

- Application initialization.
- Health-check endpoint.
- SQLite database initialization.
- Journal entry creation and retrieval.
- Invalid input handling.
- Weather API behavior when credentials are unavailable.

Run the tests and fix any failures introduced by your changes.

Do not claim tests passed unless they were actually executed.
